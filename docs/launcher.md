# 独立包启动器需求与开发文档

版本：v1.0  
日期：2026-09-12  
状态：L1 PowerShell 原型已实施；原生签名发布版待完成

## 1. 结论

可以把独立调色台交付给其他人试用，但当前的 `dist/standalone-candidate` 仍只是候选包：它通过
Windows 自带的 PowerShell 启动，不依赖 Node.js，但尚不是签名的原生启动器。因此不能把它作为
面向普通用户的最终外发物。

外发版应提供一个经过代码签名的 Windows 启动器。启动器需要做**受限的本地路径检测**，但不应做
任意磁盘扫描或照片目录扫描。它只验证自身所在的包目录、包内运行资源、用户级状态目录和本机回环
端口；不会读取用户的图片、浏览器 Profile、项目源码目录或其他应用数据。

推荐方案是：启动器自身包含一个最小静态 HTTP 服务，直接服务经过审计的 `app/` 目录。浏览器端
调色功能不需要 Node.js，因此正式外发包不应要求用户安装 Node.js，也不应依赖 `start.ps1` 或
`start.cmd`。当前 L1 PowerShell 原型已经内置最小静态服务；开发和测试工具不随候选包分发。

## 2. 范围与边界

### 2.1 目标

- 用户解压独立包后双击启动器，即可在默认浏览器打开本地调色台。
- 核心工作流在断网状态下可用：导入、预览、裁切、调色、LUT、导出、主题、语言和滤镜备份恢复。
- 用户不需要安装 Node.js、SQLite、项目服务端或开发依赖。
- 服务只监听 `127.0.0.1`，不暴露给局域网或互联网。
- 启动器可在中文路径、空格路径和常见可移动磁盘路径下稳定运行。
- 启动器不会改写包内资源、不会上传图片、不会收集遥测，也不会自动下载更新。

### 2.2 不在范围内

- 账号、上传入库、图库、审核、管理后台和完整项目 API。
- 任意文件浏览、系统文件关联、原生“打开/保存”对话框和照片管理。
- 扫描用户磁盘、图片目录、浏览器 Profile、注册表中的历史路径或其他软件目录。
- 自动提权、安装驱动、修改防火墙规则、绕过 Windows 安全策略。
- 自动联网更新；更新采用用户明确下载的新签名包。
- macOS、Linux 和移动平台；本文件的首个交付目标为 Windows x64。

## 3. 现状与发布判定

当前候选包包含受审计的 `app/`、`MANIFEST.json`、SBOM、许可证和无 Node 的 PowerShell 启动器。
它已经满足静态资源边界和回环服务的候选验收，但仍缺少：

- 无 Node.js 的全新 Windows 环境验证；
- 可双击的签名启动器；
- 受控进程复用、端口冲突提示和浏览器拉起体验；
- 启动器对中文/空格路径、可移动磁盘、损坏包和端口冲突的测试证据；
- 正式性能门槛所需的获授权 12MP / 24MP 测试样片。

因此，在这些门槛关闭前，只能把当前包发给理解候选版限制的试用者或技术评审者，不能称为普通用户
可用的正式独立包。

## 4. 产品决策与架构

### 4.1 推荐架构

```text
ColorGradeStudio.exe
  -> 解析并校验自身所在的包目录
  -> 校验 app/ 与 MANIFEST.json
  -> 建立用户级运行状态和单实例锁
  -> 在 127.0.0.1:4174 启动内置只读静态服务
  -> 等待带实例令牌的健康检查成功
  -> 用 Windows 默认浏览器打开本地 URL
  -> 监控子服务，用户退出时安全停止

浏览器
  -> app/index.html
  -> Canvas / Worker / IndexedDB / 浏览器下载
```

启动器应实现最小静态服务，不应为了服务静态 HTML 额外捆绑 Node.js。实现语言可选择 Rust、Go 或
`.NET Native AOT`；最终选型必须产出无需预装运行时的单个签名 `ColorGradeStudio.exe`。当前 L1
PowerShell 原型仅作为候选包启动器，不能作为正式分发方案。

### 4.2 建议包结构

```text
ColorGradeStudio-<version>-win-x64/
├─ ColorGradeStudio.exe        # 签名启动器与最小静态服务
├─ app/                        # 仅包含独立页面白名单资源
│  ├─ index.html
│  └─ assets/
├─ MANIFEST.json               # app 和随包说明文件的 SHA-256 清单
├─ SBOM.json
├─ LICENSES/
├─ docs/
│  ├─ README.md
│  ├─ privacy.md
│  ├─ support.md
│  └─ release-notes.md
└─ uninstall-data.ps1          # 可选，明确确认后仅清理启动器状态说明
```

包内不得出现 Node 运行时、`.env`、数据库、上传目录、图片库、完整项目页面、管理后台、测试夹具、
日志、远程更新器或任何完整项目 API 客户端。

### 4.3 启动器与浏览器数据的边界

用户的图片在当前浏览器会话内处理；用户 LUT、收藏、主题和语言由浏览器按来源保存。默认来源固定为
`http://127.0.0.1:4174`。端口改变会形成新的浏览器来源，可能看不到原有 LUT 和设置。

因此，启动器必须优先复用固定端口上的自身实例，不能在端口被占用时无提示地随机换端口。用户明确
选择临时端口时，界面必须提示“该端口拥有独立的浏览器本地数据”，并提供当前 URL 以便用户回到
原端口进行滤镜备份恢复。

## 5. 本地路径检测需求

### 5.1 必须检测的路径

| 检测对象       | 规则                                                                             | 失败处理                                          |
| -------------- | -------------------------------------------------------------------------------- | ------------------------------------------------- |
| 启动器自身目录 | 由可执行文件实际路径解析为规范绝对路径；支持 Unicode、空格和长路径               | 显示包路径无法解析，停止启动                      |
| 包根目录       | `ColorGradeStudio.exe` 的父目录；禁止通过命令行传入任意资源根目录                | 根目录不可信，停止启动                            |
| 静态资源       | 必须存在 `app/index.html` 及清单列出的资源；每个解析后的路径都必须仍在 `app/` 内 | 显示包不完整或已损坏，不启动                      |
| 清单与版本     | 校验 `MANIFEST.json` 的格式、相对路径、SHA-256 和产品版本                        | 显示完整性校验失败，不启动                        |
| 用户级状态目录 | 仅使用 `%LOCALAPPDATA%\\ColorGradeStudio\\Launcher\\`，创建并测试最小写入        | 提示无写权限，可继续以一次性模式或停止            |
| 网络位置       | 识别本地固定盘、可移动盘与 UNC 网络共享                                          | V1 支持本地与可移动盘；UNC 显示风险提示并拒绝启动 |
| 端口与实例状态 | 仅探测默认回环端口和启动器自己的锁记录                                           | 见第 6 节的端口冲突流程                           |

所有路径必须经过规范化和符号链接/重解析点解析。服务端在每次请求中也必须再次验证：请求资源解析后
仍位于 `app/` 内，并且属于编译时白名单或清单白名单。不能只依赖字符串前缀判断。

### 5.2 明确禁止的检测

- 不枚举磁盘、用户目录、桌面、下载目录或照片目录。
- 不根据注册表或环境变量猜测图片位置。
- 不读取浏览器历史、Cookie、IndexedDB 或 Profile 文件。
- 不搜索 PATH 中的 Node.js、Python、Git 或其他开发工具作为正式运行依赖。
- 不接受 `--root`、`--static-dir` 等可将服务指向任意目录的公开参数。

图片选择继续由浏览器文件选择器、拖放和剪贴板完成；启动器不知道、也不记录图片的本地路径。

## 6. 启动、实例与端口行为

### 6.1 标准启动流程

1. 用户双击 `ColorGradeStudio.exe`。
2. 启动器验证签名、包根目录、清单和应用入口。
3. 启动器取得每用户单实例锁，并读取受限的状态文件。
4. 若状态文件记录的进程仍存活，则用仅本地的实例健康检查验证包版本与随机实例令牌；验证成功时只打开浏览器，不再启动第二个服务。
5. 若没有实例，启动器绑定 `127.0.0.1:4174`，以只读根目录 `app/` 提供静态资源。
6. 静态服务返回含随机实例令牌的健康检查响应；启动器在超时前轮询该响应。
7. 启动器使用 Windows Shell 默认浏览器打开 `http://127.0.0.1:4174/`。
8. 用户关闭启动器时，启动器停止其创建的服务并删除自己的临时锁；不会清除浏览器 LUT、设置或导出文件。

启动器不得把完整 URL、包路径或异常堆栈上传。可在用户级日志中记录启动时间、启动器版本、错误码和
端口，不记录图片文件名、图片路径或浏览器数据。

### 6.2 端口冲突流程

| 情况                                    | 行为                                                             |
| --------------------------------------- | ---------------------------------------------------------------- |
| `4174` 是同版本启动器创建且实例令牌匹配 | 复用该实例并打开浏览器                                           |
| `4174` 被其他进程占用                   | 显示进程占用提示；默认不启动第二个端口                           |
| 用户选择“临时端口”                      | 只允许用户明确输入或确认可用端口；提示新端口是新的浏览器数据来源 |
| 指定端口无效、非回环或已占用            | 拒绝启动，不绑定 `0.0.0.0` 或 IPv6 公网地址                      |
| 静态服务在超时前未就绪                  | 停止自己创建的进程，给出错误码和查看日志入口                     |

健康检查必须是启动器与其静态服务之间的受限协议，例如 `GET /_launcher/health` 返回版本和本次随机
实例令牌。该接口不读取文件、不返回系统信息、不接受写操作，且不会在页面 UI 中展示。

## 7. 功能需求

### 7.1 启动器界面

- 首次启动显示产品名称、版本和“仅在本机浏览器中运行”的简短说明。
- 正常路径不显示控制台窗口；启动失败显示可复制的错误码和人工可读说明。
- 提供“打开调色台”“复制本地地址”“查看日志”“退出”四个明确操作。
- 端口冲突、完整性校验失败、包结构损坏、浏览器拉起失败、被安全软件阻止和状态目录无权限均有独立错误码。
- 中文为默认语言，支持与页面一致的英文错误文本。

### 7.2 安全与隐私

- 所有监听必须显式绑定 `127.0.0.1`；拒绝任何来自非回环地址的请求。
- 只允许 `GET` 与 `HEAD`，只服务清单内静态资源；没有 API、上传、目录列表、代理或任意文件读取。
- 使用最小环境变量集启动服务；忽略 `NODE_OPTIONS` 等会改变运行时行为的外部环境变量。
- 不请求管理员权限，不修改防火墙，不建立开机启动项。
- 可执行文件必须做 Authenticode 代码签名；发布流程记录签名时间戳、证书主体和 SHA-256。
- 启动器更新只能由用户明确下载并替换整个签名包完成；不实现后台下载和静默替换。

### 7.3 可靠性

- 以 Windows 宽字符 API 处理路径，完整覆盖中文、空格和长路径。
- 所有文件句柄、监听端口和子进程必须在异常、取消和退出时释放。
- 以原子写入方式更新状态文件，损坏状态文件只会触发重新启动，不能阻塞使用。
- 进程崩溃后下次启动能够识别陈旧锁并安全恢复。
- 浏览器无法拉起时服务可在受控超时内保留，用户可复制回环地址手动打开。
- 安装包所在目录只读时仍可运行；日志和锁不写入包目录。

## 8. 开发方案

### 8.1 代码组织

```text
launcher/
├─ README.md
├─ src/
│  ├─ bootstrap/       # 自身路径、包根与命令行解析
│  ├─ integrity/       # manifest、哈希、签名与版本验证
│  ├─ server/          # 回环静态服务与健康检查
│  ├─ instance/        # mutex、状态文件、端口和进程生命周期
│  ├─ shell/           # 默认浏览器与剪贴板操作
│  ├─ ui/              # 最小启动器窗口与本地化文案
│  └─ logging/         # 无照片路径的用户级诊断日志
├─ tests/
│  ├─ unit/
│  ├─ integration/
│  └─ e2e/
└─ packaging/
   ├─ manifest-schema.json
   └─ sign-and-package.ps1
```

静态服务实现必须独立于完整项目的 `serve.js`。它不得引入 SQLite、认证、上传、数据目录或完整项目
路由。`app/` 继续由现有 Vite 独立构建和资源白名单产生。

### 8.2 清单格式要求

现有 `MANIFEST.json` 可作为基础，外发版需要补充或冻结以下字段：

```json
{
  "schemaVersion": 2,
  "product": "Color Grade Studio",
  "version": "<semantic-version>",
  "platform": "win32-x64",
  "entry": "app/index.html",
  "defaultOrigin": "http://127.0.0.1:4174",
  "files": [{ "path": "app/index.html", "bytes": 0, "sha256": "..." }]
}
```

`path` 必须是相对 POSIX 路径；不得为空、绝对路径、包含 `..`、设备路径或符号链接逃逸。启动器在
启动前验证它，静态服务在响应前再次执行资源白名单检查。

### 8.3 发布流水线

1. 运行独立构建与边界检查：`npm run build:standalone`、`npm run check:standalone`。
2. 生成候选包、SBOM、许可证与现有清单：`npm run package:standalone`。
3. 由启动器打包步骤生成或升级清单 schema，加入启动器二进制和外发文档的哈希。
4. 在隔离 Windows x64 环境中签名 `ColorGradeStudio.exe`，验证 Authenticode 与时间戳。
5. 解包到测试路径并执行第 9 节的矩阵；保留不含个人路径和图片数据的测试报告。
6. 仅当性能、签名、干净机器、隐私与浏览器验收均通过时，生成对外分发 ZIP。

开发构建可以使用未签名二进制，但启动器必须在 UI 与日志中明确标识“开发构建”；发布构建不得允许
通过开关跳过清单或签名校验。

## 9. 验收标准与测试矩阵

### 9.1 必须通过的验收

1. 一台未安装 Node.js、SQLite、项目源码和开发依赖的 Windows x64 机器可启动完整流程。
2. 包被解压到中文路径、空格路径、超过 260 字符路径和可移动盘路径后，启动器能验证并打开页面。
3. UNC 网络共享路径被明确拒绝，不产生服务进程或状态污染。
4. `app/` 内任一文件被删除、修改或新增未清单资源时，完整性校验失败且不启动页面。
5. `4174` 的同包实例可复用；被其他进程占用时不会静默换端口或覆盖其他进程。
6. 用户明确选择临时端口时，页面可打开且提示浏览器本地数据隔离影响。
7. 断网下可导入图片、应用内置 LUT、调整、裁切、导出并使用 Worker。
8. Chrome 与 Edge 的临时独立 Profile 验收通过，无远程请求、API 或上传调用。
9. 服务只能从回环地址访问；路径穿越、编码穿越、符号链接逃逸、非法方法和目录访问均被拒绝。
10. 启动器退出、崩溃恢复和连续双击不会遗留失控进程、锁或端口。
11. 日志、状态文件和错误报告不包含图片内容、图片文件名、图片路径、浏览器 Profile 路径或用户凭据。
12. 发布 ZIP 的签名、清单、SBOM、许可证、版本说明和隐私文档全部存在且相互对应。

### 9.2 最低自动化覆盖

| 类别           | 关键场景                                                                  |
| -------------- | ------------------------------------------------------------------------- |
| 单元测试       | 路径规范化、清单解析、`..` 拒绝、哈希验证、端口校验、状态文件原子恢复     |
| 集成测试       | 回环绑定、健康检查令牌、静态白名单、重复启动、端口冲突、异常退出清理      |
| Windows 端到端 | 无 Node 机器、中文/空格/长路径、可移动盘、默认浏览器、Chrome、Edge        |
| 安全测试       | 非回环请求、目录遍历、编码路径穿越、符号链接逃逸、非 GET/HEAD 方法        |
| 隐私测试       | 断网抓包、无遥测、日志敏感信息扫描、浏览器 Profile 不访问                 |
| 回归测试       | `npm test`、`npm run check`、`npm run check:project`、`npm run test:p3-5` |

## 10. 分阶段实施

### L0：设计冻结

- 评审本文件、清单 schema 和静态服务 HTTP 契约。
- 选择 Rust、Go 或 `.NET Native AOT` 的实现语言，并记录许可证、包体积、签名和 Windows 支持理由。
- 冻结外发版的端口策略、UNC 策略、日志字段和错误码表。

### L1：最小可运行原型

- 实现自身路径解析、`app/` 白名单静态服务、回环绑定、健康检查和默认浏览器打开。
- 实现单实例锁、状态文件和包内清单哈希验证。
- 在开发机验证中文路径、空格路径、端口冲突和浏览器拉起。

### L2：发布加固

- 实现最小启动器 UI、错误本地化、用户级日志、崩溃恢复和临时端口明确确认流程。
- 进行路径穿越、重解析点、非回环请求和损坏包测试。
- 接入签名、SBOM、可复现打包和发布清单验证。

### L3：外发验收

- 在干净 Windows 机器执行完整测试矩阵。
- 使用获授权 12MP / 24MP SDR sRGB 图片完成性能门槛。
- 完成 Chrome / Edge 离线、Worker、导入、调色、导出和备份恢复验收。
- 由发布负责人确认签名、隐私文档、许可证、版本和已知限制后才允许对外发放。

## 11. 与现有工程的关系

- `dist/standalone-candidate` 是带 L1 PowerShell 启动器的候选包，不是最终用户运行时。
- `scripts/serve-standalone.cjs` 只保留在源码工程中，供开发、测试和技术评审使用，不随候选包分发。
- 启动器不得调用完整项目的 `serve.js`，不得带入数据库、账号或图库数据。
- 本文是独立包启动器的长期维护说明；外发边界以本文为准。
